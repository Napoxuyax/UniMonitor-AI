# UniMonitor AI — начальный учебный прототип

## Запуск
Python 3.11–3.13. Из каталога проекта:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```
Открыть адрес, выведенный Streamlit. Проверка ядра: `python -m pytest -q`.

## Данные
`data/demo.csv` — 420 синтетических наблюдений, 60 условных вузов, 2019–2025. Генератор: `python make_demo.py`. Для настоящих данных подготовьте CSV в UTF-8 с полями university (название), region (регион), year (год), students (численность), score (средний балл 0–100), research (объем исследований в сопоставимых единицах), income (доход в сопоставимых единицах), employment (доля трудоустроенных 0–100). Не смешивайте разные единицы и методики. Источник и единицы реальных данных необходимо документировать отдельно. Данные не загружены с официального портала.

## Алгоритмы
K-means (3 кластера), MLP-автоэнкодер (8–2–8), эвристический порог аномалий 90-й процентиль ошибки реконструкции. MLP (16–8) прогнозирует трудоустройство следующего года; Ridge и сохранение предыдущего значения — базовые модели. Последний целевой год отложен для оценки MAE/RMSE (процентные пункты). Модель не оптимизирована; тест выявил предупреждение о сходимости. Файл experiment.ipynb воспроизводит эксперимент после установки зависимостей.

## Статус
Работоспособность аналитического ядра проверена четырьмя тестами. Интерфейс Streamlit в текущей среде не запущен (зависимость отсутствует). Это стартовый проект, не завершенная ВКР: нет реального датасета, публичного репозитория, 2000 логических строк, 50 коммитов, согласования GUI и метрик, системы учетных записей или базы данных. Не выдавать демонстрационные результаты за показатели вузов. Студенту следует самостоятельно изучить, проверить и доработать код.

## Версия 0.2: хранение и доступ
Перед первым запуском задайте переменную окружения `UNIMONITOR_ADMIN_PASSWORD` (свой уникальный пароль не короче 12 символов), при необходимости `UNIMONITOR_ADMIN_LOGIN` (по умолчанию admin). В PowerShell: `$env:UNIMONITOR_ADMIN_PASSWORD = 'ваш-уникальный-пароль'`. В Bash: `export UNIMONITOR_ADMIN_PASSWORD='ваш-уникальный-пароль'`. После запуска и создания администратора удалите переменную из окружения. SQLite-файл `unimonitor.sqlite` хранит учетные записи, импортированные наборы и журнал импорта/создания пользователей. Пароли хешируются PBKDF2-HMAC-SHA256 с индивидуальной солью. Администратор создает пользователей; аналитик импортирует наборы; наблюдатель просматривает данные и аналитику. Источник импортированных данных указывается пользователем и не верифицируется автоматически. Внешнее развертывание требует отдельной проверки безопасности, TLS и ограничения попыток входа. База не предназначена для публикации в Git.

В версии 0.2 проверено 8 автоматических тестов (см. test_results_v02.txt). Предупреждение о сходимости MLP остается. Интерфейс не проверен в браузере из-за отсутствия Streamlit. Реальный набор данных, окончательная архитектура DL и публичный репозиторий пока не готовы. SQLite выбрана для локального прототипа вместо PostgreSQL; переход на серверную СУБД возможен позднее.

## Версия 0.3: временная валидация
`python run_research.py` сохраняет таблицы и графики в `research_results/`. Подбор шести MLP и трёх Ridge выполняется на расширяющихся временных выборках, последний целевой год исключается из подбора. Победитель по средней MAE валидации переобучается на всех доступных парах только после контрольной оценки. Ноутбук `temporal_experiment.ipynb` воспроизводит эксперимент. Раздел «Эксперимент моделей» запускает его из интерфейса. Данные синтетические; пять предупреждений сходимости получены при демонстрационном запуске. Результаты не подтверждают качество на официальной статистике.

## 0.4 — подготовка внешних данных

Источник-кандидат: https://tochno.st/datasets/performance — Губа К., Кучаков Р.; обработка «Если быть точным», CC BY 4.0. Первичный источник: https://monitoring.miccedu.ru/?m=vpo. Архив мониторинга 2025 относится к данным за 2024 год. Не смешивайте год публикации и отчётный год.

Модуль `import_monitoring.py` принимает широкую таблицу CSV (одна строка на вуз и год). Если исходник имеет длинный формат, сначала потребуется преобразовать показатели в столбцы на основании словаря данных и проверить уникальность идентификаторов вузов. Не заменяйте отсутствующее трудоустройство или другие показатели нерелевантными переменными. Единицы измерения и определения должны совпадать по годам. Пример карты столбцов `data/mapping_example.json` относится только к демонстрационному формату, не является проверенной картой официального набора.

```bash
python import_monitoring.py data/demo.csv data/mapping_example.json prepared --separator ',' --source 'Синтетический учебный набор'
```

Результаты: `accepted.csv`, `rejected.csv`, `quality.json` (источник, SHA-256, карта полей, пропуски, охват). Допустимый набор можно импортировать через интерфейс. Дубликаты ключей исключаются целиком для ручной проверки, пропуски не заполняются вымышленными значениями. Официальный архив в среде разработки скачать не удалось; обучение на реальных данных не выполнено.

## Версия 0.9 — многокритериальная оценка и мониторинг изменений
Разделы «Рейтинг вузов» и «Изменение данных» доступны в обоих локальных веб-интерфейсах. Рейтинг использует нормализацию min-max в пределах выбранного года и взвешенную сумму. Все пять критериев считаются положительными; веса задаёт пользователь. Это исследовательский рейтинг, не официальный рейтинг Минобрнауки. Анализ устойчивости использует 300 воспроизводимых сценариев независимого изменения исходных весов на ±25% с последующей нормализацией. Сопоставление распределений выполняется только для вузов, присутствующих в обоих годах; KS-расстояние 0,2 используется как условный порог для экспертной проверки, а не тест значимости. CSV в decision_results получены на синтетических данных. Новые тесты включают HTTP-запросы с авторизацией. Официальные данные, браузерная проверка переходов и публикация репозитория остаются открытыми задачами.

## v0.10 — сценарный прогноз
В разделе `/scenario` можно задавать относительные изменения пяти показателей от −100 до +100%. Используется фиксированная Ridge (alpha=1); влияние факторов оценивается перестановками на отложенном году. Радиус эмпирического интервала рассчитан по ошибкам последовательных валидационных периодов, без контрольного года. Это не гарантия покрытия и не причинный прогноз. Результаты учебного эксперимента находятся в `scenario_results`. Тесты: `python -m pytest -q`.

## v0.11 — реестр моделей
`python model_registry.py data/demo.csv --source "Учебный набор" --kind demo --model "Ridge alpha=1.0"` создаёт отдельную запись эксперимента в `model_runs`. Контрольная модель обучена без последнего целевого года; рабочая модель переобучена на всех доступных парах. Метрики контрольного года относятся только к первой модели. Конфигурация задаётся явно, а не подбирается по контрольной выборке. Сохраняются данные, прогнозы, версия scikit-learn и SHA-256 файлов. Администратор видит реестр в `/experiments`; обучение запускается из CLI. Joblib-файлы следует загружать исключительно из доверенного локального реестра: контрольные суммы не являются электронной подписью. Для публикации исходного кода каталог `model_runs` исключён из Git; демонстрационный манифест доступен в `registry_demo.json`. Официальная статистика не подключена.

### v0.16 — контрольный эксперимент обнаружения аномалий

`python anomaly_benchmark.py data/demo.csv` сравнивает три автоэнкодера и Isolation Forest. Обучение выполняется до предпоследнего года, пороги определяются по предпоследнему году, последний год оставляется для проверки. Аномалии вводятся искусственно в копии записей; исходные записи не являются подтверждённо нормальными. При равенстве validation AP выбирается первая конфигурация в порядке перечисления. Результаты сохраняются в anomaly_results. В защищённом интерфейсе доступен раздел «Оценка аномалий». Метрики не свидетельствуют о точности обнаружения реальных нарушений.

### Версия 0.17 — прогнозирование по многолетней истории

Модуль `lag_forecast.py` формирует окна из трёх последовательных лет (15 признаков), исключает разрывы и сравнивает Ridge, MLP, наивный прогноз и линейный тренд. Подбор параметров производится на предшествующих годах, последний целевой год используется для независимой проверки. Запуск: `python lag_forecast.py data/demo.csv --output lag_results`. Раздел защищённого веб-интерфейса: `/lag-forecast`. Результаты относятся к синтетическому набору; официальный датасет не подключён.

### Версия 0.18 — сопоставимые вузы

Рекомендации ограничены диагностикой и проверкой причин, не являются причинными выводами. Раздел `/peers` в защищённом интерфейсе. Синтетические данные; специализация и регион не учитываются. Ограничение входа: до пяти попыток с одного IP за 60 секунд, после успешного входа счётчик сбрасывается. Счётчик хранится в памяти, не является распределённым защитным механизмом. Повторный вход в том же браузере отзывает предыдущий токен. При чтении набора проверяется SHA-256 сохранённого CSV; несовпадение приводит к отказу. SHA-256 без секретного ключа обнаруживает случайное повреждение, но не защищает от администратора, способного изменить и данные, и хеш. Проверено 111 тестов (test_results_v1rc4.txt). Для публичного развёртывания необходимы HTTPS, отдельный аудит безопасности и настройка прокси. Официальные данные не подключены.
